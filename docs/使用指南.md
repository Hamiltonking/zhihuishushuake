# ZHS 使用指南（Ubuntu）

> 面向实际刷课的完整流程：装环境 → 登录 → 看指标 → 刷学习程度 → 刷掌握度 → 挂机与排错。
> 项目本身的命令说明见 [tutorial.md](tutorial.md)，本文补充**在 Ubuntu 上真实跑通**的做法和踩过的坑。

---

## 1. 两个指标，别搞混

AI 智慧课程里有两个独立进度，工具的两组命令分别对应：

| 指标 | 接口字段 | 靠什么涨 | 对应命令 |
|------|----------|----------|----------|
| **学习程度** | `schedule` | 看完知识点视频 / PPT / 文本资源 | `zhs play` |
| **掌握度** | `mastery` | 做知识点作业并拿到分数 | `zhs homework` |

- 视频刷完，`schedule` 到 100%，但 `mastery` 可能还是 0——**必须做作业**。
- 掌握度是各知识点作业分数的汇总，作业分数由服务端 `highMasteryScore` 决定，答完就固定，不会因为重看视频而变化。
- AI 课程有没有考试，用 `zhs exam --type ai` 扫一遍就知道；本仓库实测的习概课程 `exam_tasks = 0`，即掌握度**只由作业决定**。

查当前指标（把课程 ID 换成自己的）：

```bash
cd ~/shua/zhs && .venv/bin/python - <<'PY'
import json
from pathlib import Path
from zhs.config import ConfigManager
from zhs.session import ZhsSession
from zhs.ai.course import AiCourseManager
from zhs.utils.cookie import list_to_cookies

c = ConfigManager().load()
s = ZhsSession(c)
s.cookies = list_to_cookies(json.loads(Path("personal/cookies.json").read_text()))
for d in AiCourseManager(s).get_ai_course_list():
    print(f"{d['courseName']}  courseId={d['courseId']} classId={d.get('classId')} "
          f"学习程度={d.get('schedule')}% 掌握度={d.get('mastery')}%")
PY
```

## 2. 环境要求（Linux / Ubuntu）

| 项 | 要求 | 说明 |
|----|------|------|
| Python | **3.13 或 3.14** | `>=3.13,<3.15`。Ubuntu 24.04 自带的是 3.12，**不能直接用** |
| 系统 | 任意 x86_64 Linux | 官方 CI 跑在 ubuntu-24.04 上；包是 `py3-none-any` 纯 Python 轮子 |
| 网络 | 能访问 PyPI 与 `*.zhihuishu.com` | 国内网络一般直连即可 |

### 2.1 拿到 Python 3.13

三选一：

```bash
# A. 系统里已有（Ubuntu 24.04 常见于手动安装/deadsnakes）
python3.13 -V

# B. deadsnakes PPA
sudo add-apt-repository ppa:deadsnakes/ppa && sudo apt update
sudo apt install python3.13 python3.13-venv

# C. 用 uv 托管 Python（不需要 sudo）
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.13
```

### 2.2 安装 zhs

Ubuntu 的系统 Python 受 PEP 668 保护，`pip install` 到系统环境会报
`externally-managed-environment`，**必须用虚拟环境**。

```bash
# 方式 A：直接装 PyPI 发布版（推荐给只用不改的人）
python3.13 -m venv ~/.venvs/zhs
~/.venvs/zhs/bin/pip install -U zhs

# 方式 B：从源码装（要改代码 / 跟仓库走）
cd ~/shua/zhs
python3.13 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/zhs --version

# 方式 C：uv（开发用，含测试依赖）
cd ~/shua/zhs && uv sync --dev && uv run zhs --version
```

> 之后所有命令都走 `.venv/bin/zhs`，或先 `source .venv/bin/activate` 再用 `zhs`。

## 3. 目录结构：配置在仓库根，个人数据在 `personal/`

```
~/shua/zhs/
├── src/  tests/  docs/  scripts/    # 源码，入库
├── tools/                           # 辅助脚本（扫码 / 续跑 / 错题导出），入库
├── config.toml                      # ★ 配置（含 API Key，chmod 600，不入库）
├── config.toml.bak                  # 改动前的备份（不入库）
├── .gitignore                       # 忽略 personal/、.zhs、config.toml
├── personal/                        # ★ 个人数据，不入库
│   ├── cookies.json                 # 登录态
│   ├── execution.json               # zhs fetch 的课程列表
│   ├── qrcode.png                   # 扫码登录二维码
│   ├── cache/                       # 题库/答案缓存（SQLite）
│   ├── logs/                        # 日志，按天切分，保留 30 天
│   ├── AiDownloadCache/             # AI 课程 PPT 缓存
│   ├── questions_all.md             # 全量题目报告
│   └── wrong_questions.md           # 错题本
└── .zhs/                            # 工具写死的相对数据目录（真目录 + 软链）
    ├── config.toml -> ../config.toml
    ├── cookies.json -> ../personal/cookies.json
    ├── execution.json -> ../personal/execution.json
    ├── qrcode.png    -> ../personal/qrcode.png
    ├── cache         -> ../personal/cache
    ├── logs          -> ../personal/logs
    └── AiDownloadCache -> ../personal/AiDownloadCache
```

**为什么这样摆**

`zhs` 源码把数据目录写死成相对路径 `.zhs`（见 `src/zhs/utils/path.py`），改源码不现实。所以 `.zhs` 做成一个**真目录**，里面每一项都是指向真实位置的软链：

- 配置文件放在**仓库根** `config.toml`，`.zhs/config.toml` 软链过去 —— 配置不算个人数据，单独放
- Cookie / 日志 / 缓存 / 二维码等都放进 `personal/`，`.zhs/` 里只留软链

软链丢了按上表重建即可，例如：

```bash
cd ~/shua/zhs
ln -sfn ../config.toml .zhs/config.toml
ln -sfn ../personal/logs .zhs/logs
```

**结论：始终在 `~/shua/zhs` 目录里运行**。换目录运行 = `./.zhs` 指向别处，配置和 Cookie 全部从零开始。

## 4. 初始化与配置

```bash
cd ~/shua/zhs
.venv/bin/zhs init              # 首次生成配置（经符号链接写进 personal/）
chmod 600 config.toml  # 有 API Key，收一下权限
```

### 4.1 接自定义大模型（DeepSeek 示例）

AI 课程默认走智慧树内置 AI（准确率低），知到作业/考试**没有**内置 AI，必须自配。推荐 OpenAI 兼容接口：

```toml
[ai]
enabled = true
use_builtin_ai = false                      # 关掉内置 AI
api_key = "sk-你的key"
base_url = "https://api.deepseek.com/v1"    # DeepSeek
model = "deepseek-chat"                     # 或 deepseek-reasoner
max_token = 27900                           # 只用于 prompt 截断，不是输出上限
stream_timeout = 120.0
stream_idle_timeout = 30.0
```

配完先自检，能打印出答案标记才算通：

```bash
.venv/bin/python - <<'PY'
from zhs.config import ConfigManager
from zhs.llm.factory import LLMProviderFactory
from zhs.session import ZhsSession
c = ConfigManager().load()
p = LLMProviderFactory.create(c.ai, session=ZhsSession(c), course_id="x", course_name="test")
print(p.completion("中华人民共和国成立于哪一年？把答案放在 ```answer 和 ``` 之间。"))
PY
```

> `completion()` 依赖 ` ```answer ` 标记解析，随便问一句（不带标记要求）会报「未返回有效答案」，那是正常的。

### 4.2 掌握度阈值

```toml
[homework]
ai_homework_threshold = 80   # 掌握度 > 80 才算达标，≤80 会重做
threshold = 100              # 知到作业的达标线
max_submit = 0
delay_min = 1.0
delay_max = 2.0
```

判断逻辑在 `src/zhs/ai/course.py`：

- `mastery_score > ai_homework_threshold` → 跳过，不再做（**严格大于**，正好 80 分仍会重做）；
- 否则进入作业循环，每次重做后重新查询分数，直到达标；
- `max_submit` **对 AI 课程作业无效**（只作用于知到），唯一兜底是「分数 < 30 且已重试 > 4 次」才放弃。所以卡在 30~80 之间的知识点理论上会一直重刷，**挂机时务必盯一下**，必要时用「只补 0 分」模式。

## 5. 登录

```bash
cd ~/shua/zhs
.venv/bin/zhs login --show-in-terminal   # 终端里直接刷二维码
```

二维码同时写到 `personal/qrcode.png`（238×238）。三种看法：

| 方式 | 命令 | 适用 |
|------|------|------|
| 终端字符画 | `zhs login --show-in-terminal` | 纯 SSH，但压成 39 列，**不好扫** |
| 图片文件 | `xdg-open personal/qrcode.png` 后放大 | 有桌面 |
| 网页（推荐） | 见 5.1 | 大图 + 自动换新 |

登录成功后 `personal/cookies.json` 落盘，后续命令自动复用。

### 5.1 网页扫码（本机脚本）

`tools/qr_login.py`：起本地网页 + 后台跑 `zhs login`，二维码放大到 380px 并每 1.5 秒自动刷新，页面实时显示「等待扫码 / 已确认 / 登录成功」。只监听 `127.0.0.1`，扫码成功后自动关服务。

```bash
cd ~/shua/zhs && .venv/bin/python tools/qr_login.py     # 自动开浏览器，默认 8765 端口
```

可选参数：`--port 8800`（换端口）、`--no-browser`（不自动开浏览器，自己访问打印出的地址）。

## 6. 怎么拿到课程 ID

几乎所有命令都要 `-c <courseId>`，AI 课程还要 `classId`。三种拿法，**推荐第 1 种**。

### 6.1 `zhs fetch`（最稳，能一次拿全）

```bash
cd ~/shua/zhs
.venv/bin/zhs fetch
```

输出（真实示例）：

```
登录状态有效
[知到] 1 门课程
  大学美育 (courseId=1000094701)
[Hike] 0 门课程
[AI] 3 门课程
  大学物理2026年秋冬学期 (courseId=2093890346100523008, classId=245825)
  习近平新时代中国特色社会主义思想概论2026年秋冬学期 (courseId=2094350321505583104, classId=254981)
  西北工业大学·概率论与数理统计2026年秋冬学期 (courseId=2093900999738916864, classId=259895)
```

- **知到**：只有 `courseId`，直接用 `-c 1000094701 --type zhidao`
- **AI**：`courseId` 和 `classId` 成对出现，用 `-c courseId:classId --type ai`
- **Hike**：只有 `courseId`，`-c 12345 --type hike`（一般可省略 `--type` 自动识别）

结果同时写进 `personal/execution.json`，以后不用重跑，直接查：

```bash
cat personal/execution.json

# 只想看 AI 课程的 id 对
.venv/bin/python -c "
import json;d=json.load(open('personal/execution.json'))
for c in d if isinstance(d,list) else d.get('ai',[]): print(c)
"
```

### 6.2 从浏览器地址栏里认

在网页上打开课程，地址栏里就带着 ID。对照下表：

| 页面 | URL 形态 | 其中哪段是 ID |
|------|----------|---------------|
| 知到视频页 | `studyvideoh5.zhihuishu.com/stuStudy?recruitAndCourseId=1000008156` | `recruitAndCourseId`（这是 recruitId，**不是** courseId） |
| 知到作业页 | `onlineexamh5new.zhihuishu.com/stuExamWeb.html#/webExamList/dohomework/...` | 只能用 `--url`，别手工拆 |
| AI 课程首页 | `ai-smart-course-student-pro.zhihuishu.com/singleCourse/knowledgeStudy/2094350321505583104/254981` | 倒数第二段 `courseId`，最后一段 `classId` |
| AI 学习页 | `.../learnPage/2094350321505583104/12345/254981` | 三段依次是 `courseId` / `nodeUid` / `classId` |
| AI 考试页 | `.../testDetail/2094350321505583104/254981/9001/9002/...` | 前两段 `courseId` / `classId` |

**偷懒办法**：直接把整条 URL 丢给 `--url`，工具自己解析，不用管哪段是哪个 ID：

```bash
zhs play --url "https://ai-smart-course-student-pro.zhihuishu.com/singleCourse/knowledgeStudy/2094350321505583104/254981"
zhs exam --url "https://ai-smart-course-student-pro.zhihuishu.com/testDetail/2094350321505583104/254981/9001/9002/xxx"
```

> 注意：知到视频页的 `recruitAndCourseId` 是 recruitId，只有 `--url` 能正确解析它；手写 `-c` 时要用 `zhs fetch` 输出的 `courseId`，两者不是一回事。

### 6.3 `zhs fetch` 失败时

登录态失效会打印「登录状态已过期」，重新登录再 fetch：

```bash
.venv/bin/python tools/qr_login.py     # 网页扫码
.venv/bin/zhs fetch
```

## 6.4 常用命令

```bash
# 刷学习程度（视频/PPT/文本全过）
zhs play -c 2094350321505583104:254981 --type ai

# 刷掌握度（做作业）
zhs homework -c 2094350321505583104:254981 --type ai

# 考试（没有考试任务时什么也不做）
zhs exam -c 2094350321505583104:254981 --type ai
```

常用参数：

| 参数 | 作用 |
|------|------|
| `-s 1.5` | 视频倍速（最高 2.0） |
| `-l 30` | 限时 30 分钟后停 |
| `--proxy socks5://127.0.0.1:7890` | 走代理 |
| `-d` | debug 日志 |
| `--console-log` | 日志同时打到控制台 |
| `--max-submit N` | 知到作业重做上限（AI 作业无效） |
| `--url "<浏览器地址>"` | 直接贴页面 URL 自动解析课程 |

> `socks5://` 代理需要额外装依赖：`.venv/bin/pip install "httpx[socks]"`，否则用 `http://` 代理。

## 7. 控制作业节奏：只补 0 分 / 每个知识点最多 N 次

`tools/resume_homework.py` 比原生命令多两个开关。它同时会跳过启动时的 CAS 票据校验
（`CASTGC` 过期后直接跑 `zhs homework` 会误报「登录状态已过期」，其实 API 会话还有效）。

### 7.1 每个知识点最多 N 次（推荐）

```bash
cd ~/shua/zhs
.venv/bin/python tools/resume_homework.py 2094350321505583104 254981 --max-tries 2
```

- 掌握度 `> ai_homework_threshold`（当前 80）→ 直接跳过；
- 否则最多做 N 次；中途某次拿到 81+ 就提前停，不浪费剩余次数；
- 默认逻辑是不限次数（只要不到阈值就一直重刷），`max_submit` 对 AI 课程无效。

### 7.2 只补 0 分

```bash
.venv/bin/python tools/resume_homework.py 2094350321505583104 254981 --only-zero
```

掌握度只要不是 0（哪怕 67 分）就一律不碰。


> 脚本读取 `personal/cookies.json`，日志仍写进 `personal/logs/`，与 `zhs` 原生命令共用同一批数据。

## 7.5 错题本：看错在哪、正确答案是什么

`tools/wrong_report.py` 从缓存里把做错的题连正确答案一起导出来（服务端判分时会回传正确选项）：

```bash
cd ~/shua/zhs
.venv/bin/python tools/wrong_report.py                 # 默认习概课程
.venv/bin/python tools/wrong_report.py --course 123456  # 其他课程
```

- 终端打印前 10 道（题干、你答的、正确答案）
- 完整清单写入 `personal/wrong_questions.md`（Markdown 表格，可直接打开看）
- 统计口径：每道题取**最近一次**作答结果；只统计缓存里出现过的题

> 顺带：作业现在也启用了「跨卷按题干复用答案」（`HomeworkCtx._cross_exam_search = True`）。
> 同一道题以相同题干出现在另一份卷子时，直接复用服务端之前回传的正确答案，不再让模型重答。

## 7.6 从指定位置开始跑

每次运行默认从课程第一个知识点开始扫，扫到目标位置要花好几分钟。加起始参数可以直接跳过去：

```bash
# 按知识点/主题名关键字（第一个匹配到的就是起点）
.venv/bin/python tools/resume_homework.py 2094350321505583104 254981 --only-zero --start 全面从严治党

# 按知识点序号（1 开始，课程结构顺序）
.venv/bin/python tools/resume_homework.py 2094350321505583104 254981 --only-zero --start-index 178
```

- 起点**之前**的知识点完全不处理：不查作业、不联网、不读 PPT
- 启动时会打印 `从第 178 个知识点开始：反腐败必须永远吹冲锋号`
- 关键字没匹配到时会在 stderr 警告，并且本次不处理任何知识点

想知道自己在第几个，看日志里最近的主题名，或先不加参数跑一次看输出顺序。

## 7.7 AI 课程推荐流程（两遍法）

### 步骤 0：先刷学习程度，顺序按课程类型定

| 课程类型 | 推荐顺序 | 原因 |
|---|---|---|
| 只有 PPT / 文本、没有视频 | **先刷学习程度**（`zhs play`） | 很快，几下就 100% |
| 有视频 | **先刷掌握度**（`zhs homework`） | 视频要按真实时长挂机，作业先做不耽误 |

```bash
# 无视频课程：先学习程度
zhs play -c <courseId>:<classId> --type ai
```

### 第一遍：全量摸底，每个知识点只做一次

```bash
.venv/bin/python tools/resume_homework.py <courseId> <classId> --max-tries 1
```

- `--max-tries 1` = 每个知识点**只做一次**，不管拿多少分都收手
- **所有题目（不只错题）都会记录**：服务端判分回传的正确答案 + 你提交的答案都存在
  `personal/cache/questions_bank.db`
- 导出可读清单：

```bash
.venv/bin/python tools/wrong_report.py --all     # → personal/questions_all.md（含对/错标记）
```

> 想让第一遍覆盖**全部**知识点，把阈值临时调到 100（只有满分的才会被跳过）：
> `[homework] ai_homework_threshold = 100`

### 第二遍：只补没达阈值的，每个知识点最多 3 次

```bash
.venv/bin/python tools/resume_homework.py <courseId> <classId> --max-tries 3
```

- 只处理掌握度 **没有达到阈值** 的知识点，达标的直接跳过
- 每个知识点最多试 3 次，中途超过阈值就提前停
- 阈值可改（`config.toml`）：

```toml
[homework]
ai_homework_threshold = 80   # 掌握度 > 80 视为达标；可改成 85 / 90
```

- **输出里带阈值**，日志形如：

```
作业结束: 以伟大自我革命引领伟大社会革命 当前 79 分 (阈值=80, 已尝试 3 次)
```

### 收尾：看错题

```bash
.venv/bin/python tools/wrong_report.py          # → personal/wrong_questions.md
```

## 8. 挂机跑长任务

一节课 180 多个知识点，作业要跑 1~5 小时。用 `setsid nohup` 脱离终端，关窗口也不会断：

```bash
cd ~/shua/zhs
setsid nohup .venv/bin/python tools/resume_homework.py \
  2094350321505583104 254981 --only-zero \
  > personal/logs/homework.log 2>&1 < /dev/null &
```

看进度（以 `zhs_YYYY-MM-DD.log` 为准，重定向到文件的 stdout 有缓冲，不实时）：

```bash
grep -c "作业结果" ~/shua/zhs/personal/logs/zhs_$(date +%F).log   # 已完成次数
tail -f ~/shua/zhs/personal/logs/zhs_$(date +%F).log              # 实时日志
```

停止：

```bash
pkill -f "[r]esume_homework"     # 方括号写法避免匹配到自己这条命令
```

## 9. 排错

| 现象 | 原因 | 处理 |
|------|------|------|
| `externally-managed-environment` | PEP 668 | 用 venv，别往系统 Python 装 |
| `requires-python >=3.13` 装不上 | 系统 Python 是 3.12 | 装 3.13 后重建 venv |
| 配置/Cookie 全没了 | 换了运行目录，`./.zhs` 指向别处 | 固定 `cd ~/shua/zhs` 再运行 |
| `personal/` 里的改动没生效 | `.zhs` 符号链接丢失 | `ln -s personal .zhs` |
| `登录状态已过期` 但 `zhs fetch` 还能用 | CAS 票据过期，API 会话未过期 | 用 `resume_homework.py` 绕过，或重新 `zhs login` |
| `file is not a database` | 缓存 SQLite 被写坏 | `mv personal/cache/questions_bank.db{,.bad}`，会自动重建 |
| 二维码扫不动 | 终端 39 列字符画 | 用 `qr_login.py` 网页版 |
| 作业卡在 60~80 分反复重刷 | `mastery > 阈值` 才停 | 调低 `ai_homework_threshold`，或 `--only-zero` |
| 全部作业失败并提示鉴权 | Cookie 真过期 | 重新 `zhs login` |

日志级别在 `[display] log_level` 调成 `DEBUG`，配合 `-d` 能看到每个请求。

## 10. 费用与风险

- 自配 LLM 后每道题一次调用（带 PPT 上下文，通常几千 token）。一节课上百个知识点、每个多轮重做，建议先在 DeepSeek 控制台设个额度上限。
- 工具会模拟进度上报，**违反智慧树平台条款**，学校也可能认定为学术不端，异常进度/异地登录有风控风险，自行判断。
- 许可证 GPL-3.0-only：自用随意，分发需同样开源。

## 11. 辅助脚本（`tools/`）

三个脚本放在仓库的 `tools/` 里，随仓库走（会入库）。它们不引入新依赖，直接调用 `zhs` 包，所以**必须在仓库根目录运行**，并且用 venv 里的 python：

```bash
cd ~/shua/zhs
.venv/bin/python tools/<脚本>.py ...
```

### 11.1 `tools/qr_login.py` —— 网页扫码登录

**解决什么**：终端二维码被压成 39 列字符画，手机很难扫；`zhs login` 又必须等扫码才能继续。

**做什么**：起一个只监听 `127.0.0.1` 的小网页，同时后台跑 `zhs login`；把二维码放大到 380px、每 1.5 秒自动换新（二维码过期会自动重新获取），页面上实时显示「等待扫码 / 已扫码请确认 / 登录成功」。

```bash
.venv/bin/python tools/qr_login.py            # 自动打开浏览器，默认 8765 端口
.venv/bin/python tools/qr_login.py --port 8800 --no-browser
```

| 参数 | 作用 |
|------|------|
| `--port` | 监听端口，默认 8765 |
| `--no-browser` | 不自动开浏览器，自己访问打印出的地址 |

登录成功、服务自动关闭；Ctrl+C 会连带结束子进程（不会留孤儿进程）。

### 11.2 `tools/resume_homework.py` —— 掌握度续跑器

**解决什么**：

1. `zhs homework` 启动时会做 CAS 票据校验，票据过期就报「登录状态已过期」直接退出——即使 API 会话还有效。本脚本跳过校验，只用本地 Cookie 恢复会话。
2. 原生命令没有「每个知识点最多几次」「从第几个开始」的控制，这里补上。

```bash
.venv/bin/python tools/resume_homework.py <courseId> <classId> [选项]
```

| 参数 | 作用 |
|------|------|
| `--only-zero` | 只做掌握度仍为 0 的知识点（做过一次就不再碰） |
| `--max-tries N` | 每个知识点最多尝试 N 次；中途超过阈值就提前停 |
| `--start 关键字` | 从名称包含该关键字的知识点/主题开始，之前的完全不处理 |
| `--start-index N` | 从课程第 N 个知识点开始（1 开始） |

不加 `--max-tries` 时按阈值（`ai_homework_threshold`）判断，达标即停，不达标会一直重试。

### 11.3 `tools/wrong_report.py` —— 题目 / 错题导出

**解决什么**：服务端判分会回传每题的正确答案，这些数据都躺在缓存库里，但工具没有查看入口。

```bash
.venv/bin/python tools/wrong_report.py          # 只导错题 → personal/wrong_questions.md
.venv/bin/python tools/wrong_report.py --all    # 全部题目（含做对的）→ personal/questions_all.md
```

| 参数 | 作用 |
|------|------|
| `--all` | 包含做对的题，默认只导错题 |
| `--course ID` | 指定课程，默认 2094350321505583104 |
| `--out PATH` | 自定义输出路径 |

输出的 Markdown 表格包含：题号、题干、你答的、正确答案、✅/❌、题型、时间。

> 想改默认课程 ID，直接改脚本里的 `DEFAULT_COURSE`。
